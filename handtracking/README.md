# Quest Hand Streamer (проект «УМНИК» 0117635)

Модуль `handtracking/` общего репозитория [EMG-handtracking](../README.md).
Все относительные пути и команды ниже приведены от папки `handtracking/`,
если явно не указан другой рабочий каталог. Из корня репозитория сначала выполните:

```sh
cd handtracking
```

Общие правила Git находятся в корне репозитория; отдельного вложенного репозитория нет.

Регистратор кинематики рук на Meta Quest 3: цветной passthrough, отслеживание обеих рук,
непредсказанные позы (`OVRPlugin.GetUnextrapolatedHandState`) с исходными метками `SampleTimeStamp`,
передача на ПК по UDP (Wi-Fi), запись на ПК и резервная запись на Quest. В дальнейшем — источник
кинематической разметки для синхронной записи с ЭМГ-браслетом.

Это рабочий прототип. Частота, задержки и пригодность Quest как источника разметки ещё **не измерены
на устройстве** — см. раздел «Что проверить при первом запуске».

```
QuestHandStreamer/          Unity 6.3 (6000.3.28f1) проект для Quest 3
  Assets/HandStreamer/Runtime/   HandSampler (чтение рук), UdpLink (связь), LogWriter (резервная запись),
                                 HandStreamerHud (HUD у краёв поля зрения), HandStreamerApp (управление)
  Assets/HandStreamer/Editor/    меню HandStreamer: настройка проекта, создание сцены, сборка APK
pc-receiver/                Python 3 (только стандартная библиотека)
  receiver.py                    приёмник, синхронизация часов, запись сессий
  convert.py                     журнал -> CSV + отчёт о качестве
  viewer.py                      3D-просмотрщик записей (.qhslog)
  fake_quest.py                  имитатор Quest для проверки без шлема
docs/protocol.md            формат пакетов, временные домены, формат журнала
```

## 1. Что нужно доделать в окружении

1. **Активировать лицензию Unity.** Unity Hub → войти в аккаунт → Preferences → Licenses → Add →
   Get a free personal license. Без неё редактор не запускается (в том числе в batch-режиме).
2. **Добавить модуль Android** к редактору 6000.3.28f1: Unity Hub → Installs → ⚙ у 6000.3.28f1 →
   Add modules → **Android Build Support** с подпунктами **OpenJDK** и **Android SDK & NDK Tools**.
   Сейчас у обоих установленных редакторов есть только Windows-модуль.
3. Quest: Developer Mode в приложении Meta Horizon, при первом USB-подключении — разрешить USB debugging.
   ADB уже есть в Meta Quest Developer Hub: `C:\Program Files\Meta VR Developer Hub\resources\bin\adb.exe`.

## 2. Открыть и настроить проект

1. Unity Hub → Projects → Add → Add project from disk → папка `QuestHandStreamer`.
   При первом открытии Unity скачает пакеты (Meta XR Core SDK 209.0.0 из реестра
   `npm.developer.oculus.com`, OpenXR 1.16.1) и создаст недостающие файлы настроек — это займёт время.
2. File → Build Profiles → Android → **Switch Platform**.
3. Меню **HandStreamer → 1. Настроить проект для Quest 3** — задаёт всё нужное автоматически:
   Player Settings (IL2CPP, ARM64, minSdk 32, Vulkan, INTERNET), OpenXR loader для Android, группу
   функций Meta XR и Meta Quest Support (с `ForceRemoveInternetPermission = false`), Hand Tracking
   Support = Hands Only, Hand Tracking Frequency = High, Passthrough = Required,
   **Hand Skeleton Version = OpenXR** (без неё непредсказанные позы недоступны).
4. Меню **HandStreamer → 2. Создать сцену** (`Assets/Scenes/HandStreamer.unity`: OVRCameraRig с
   passthrough-подложкой, Floor Level, объект HandStreamerApp).
5. Meta → Tools → Project Setup Tool: проверить, что нет невыполненных **Required**-пунктов.
   «Fix All» для рекомендуемых пунктов применяйте осознанно — он меняет настройки, которые не проверялись.

Шаги 2–4 уже выполнены в репозитории (batch-режим, 12.11.2026). Без редактора то же самое делает:
`Unity.exe -batchmode -quit -projectPath QuestHandStreamer -executeMethod HandStreamer.EditorTools.HandStreamerSetup.BatchSetup`.

Hand Tracking Frequency = High включает Fast Motion Mode. Его влияние на точность и частоту отсчётов
нужно сравнить с режимом Low на устройстве. Режим Wide Motion Mode (выводимые позы вне поля зрения камер)
для эталонной разметки не включать.

## 3. Сборка и установка

**HandStreamer → 3. Собрать APK** (Development build) → `QuestHandStreamer/Builds/QuestHandStreamer.apk`.
Без редактора: `-executeMethod HandStreamer.EditorTools.HandStreamerSetup.BuildApk`.
Установка — подключить Quest по USB и перетащить APK в Meta Quest Developer Hub или:

```bash
"/c/Program Files/Meta VR Developer Hub/resources/bin/adb.exe" install -r QuestHandStreamer/Builds/QuestHandStreamer.apk
```

Приложение появится в библиотеке Quest в разделе «Неизвестные источники».

## 4. Приём на ПК

ПК и Quest — в одной Wi-Fi-сети (лучше 5 ГГц, без изоляции клиентов). При первом запуске Windows
спросит разрешение брандмауэра для Python — разрешить для частной сети.

```bash
cd pc-receiver
python receiver.py
```

ПК рассылает широковещательный маяк, Quest находит его автоматически. Если маяк не проходит
(гостевая сеть, роутер режет broadcast) — в HUD нажать «Адрес ПК» и ввести IP компьютера,
либо запустить приёмник с `--quest-ip <IP Quest>`.

### HUD в шлеме и управление руками

HUD жёстко закреплён за головой и вынесен к краям поля зрения:

| Где | Что |
|---|---|
| вверху слева | связь с ПК, частота отсчётов каждой руки (зелёный — трек, жёлтый — низкая уверенность, оранжевый — нет трека) |
| вверху справа | индикатор записи, длительность, объём локальной копии |
| внизу по центру | кнопки «● ЗАПИСЬ / ■ СТОП», «Адрес ПК», «Скелет: вкл/выкл», «Скрыть» |
| внизу справа | маленькая кнопка «Меню», когда кнопки скрыты |

Управление полностью без контроллеров:
- **нажатие** — навести луч руки на кнопку (луч появляется только над элементами HUD) и сделать щипок
  большим и указательным пальцами;
- **показать/скрыть кнопки** — повернуть ладонь (любой руки) к лицу, задержать на ~0,25 с и сделать щипок;
  либо кнопки «Скрыть»/«Меню»;
- при начале записи кнопки скрываются автоматически.

Щипок распознаётся по скелету — кончики большого и указательного пальцев ближе 1,6 см (отпускание —
дальше 2,6 см, с поправкой на размер руки): при OpenXR-скелете OVRPlugin не передаёт `Pinches`/`PinchStrength`
(проверено на Quest 3, SDK 209). Нормаль ладони — −Y сустава Palm. Каждый щипок пишется в logcat
(`[HandStreamer] ui pinch …`).

**Скелет поверх рук.** Кнопка «Скелет» включает наложение считываемого скелета (26 суставов) прямо на руки —
те же данные, что идут в запись: непредсказанная поза на момент захвата. Поэтому на быстрых движениях скелет
заметно отстаёт от руки (задержка конвейера трекинга ≈ 25–45 мс) — это ожидаемо и наглядно показывает, что
метка `SampleTimeStamp` относится к моменту захвата, а не к моменту показа. Цвета как в просмотрщике: левая —
синяя, правая — оранжевая, низкая уверенность — жёлтая, нет трекинга — серая. Состояние сохраняется
(`showSkeletonOverlay` в `config.json`).

Положение элементов настраивается без пересборки в `config.json` на шлеме: `hudDistance`, `hudStatusYaw`,
`hudStatusPitch`, `hudControlsPitch`, `hudHandleYaw`, `hudControlsVisibleOnStart`, `hudAutoHideControlsOnRecord`,
`showSkeletonOverlay`.

Запись также управляется из консоли приёмника: `r [метка]` — начать, `s` — остановить.

Сессия: `pc-receiver/recordings/<дата>_<session>/pc.qhslog`. Разбор:

```bash
python convert.py recordings/<папка сессии>
```

Получаются `hands.csv` (все суставы, время захвата в доменах Quest и ПК), `sync.csv`, `events.jsonl`,
`status.jsonl`, `report.json` (частоты, потери, перестановки, модель часов, задержки, проверка
временных доменов).

Просмотр записи в 3D (только стандартная библиотека Python):

```bash
python viewer.py recordings/<папка сессии>
```

Без аргумента откроется диалог выбора файла; можно открыть и резервную копию с Quest. Мышь: левая кнопка —
вращение, правая — сдвиг, колесо — масштаб. Пробел — пуск/пауза, ←/→ — кадр (Shift — секунда), +/− —
скорость, A — оси суставов, L — подписи, T — след кончиков пальцев, G — сетка, 1/2/3 — виды, R — сброс.
`--at 30` — открыть с 30-й секунды, `--axes` — сразу с осями. На шкале времени отмечены события
потери (красные) и восстановления (зелёные) трекинга.

Проверка ПК-части без шлема:

```bash
python receiver.py --duration 20
```

```bash
python fake_quest.py --duration 15
```

## 5. Резервная запись на Quest

Каждая запись дублируется на шлеме в `.../files/recordings/*.qhslog` (тот же формат). Забрать
(в Git Bash `MSYS_NO_PATHCONV=1` нужен, иначе путь `/sdcard/...` подменяется путём Git):

```bash
MSYS_NO_PATHCONV=1 "/c/Program Files/Meta VR Developer Hub/resources/bin/adb.exe" pull /sdcard/Android/data/com.umnik.questhandstreamer/files/recordings ./quest-recordings
```

```bash
python pc-receiver/convert.py quest-recordings/<файл>.qhslog
```

Настройки — `/sdcard/Android/data/com.umnik.questhandstreamer/files/config.json`
(`pcIp`, порты, `displayFrequency`, `allowExtrapolatedFallback`). Резервный режим с экстраполированными
позами по умолчанию **выключен**; если его включить, каждый такой кадр помечается `source = 2`.

Датчик приближения: при снятии шлема приложение ставится на паузу (в журнал пишется `app_paused`).
Для экспериментов на столе его можно временно отключить через Meta Quest Developer Hub.

## 6. Результаты первого запуска (12.11.2026)

Quest 3, Horizon OS build 52433670048800520 (Android SDK 34), OVRPlugin 1.209.0, OpenXR, скелет OpenXR,
Hand Tracking Frequency = High, дисплей 72 Гц. Wi-Fi 6 (Quest) → роутер → Ethernet (ПК), VPN на обоих
устройствах для локальной сети отключены. Одна сессия 61,8 с, руки перед собой, без нагрузки на сеть.

- [x] Непредсказанные позы доступны для обеих рук, источник во всех кадрах — `source = 1`.
- [x] 26 суставов, позиции и ориентации присутствуют.
- [x] Частота новых отсчётов **50 Гц** на руку (интервал 20 мс; 7 и 5 интервалов по 40 мс из ~3085 —
      пропуски на стороне трекинга, не сети: `frame_index_gaps = 0`). Частота дисплея 72 Гц ≠ частота трекинга.
- [x] `SampleTimeStamp` лежит в домене `GetTimeInSeconds`: захват → отправка 23–44 мс (медиана 33 мс),
      отрицательных значений нет. Это задержка конвейера трекинга Quest, а не сети.
- [x] ovr ↔ Stopwatch — одни часы: разность ≈ 1 мкс, разброс 0,055 мс, дрейф ≈ 0.
- [x] Синхронизация Quest ↔ ПК: RTT мин. 1,7 мс, погрешность ±1,2 мс, дрейф ≈ 10 ppm.
- [x] Захват → приём на ПК: медиана 36 мс, p95 46 мс, макс. 79 мс.
- [x] Потери по `seq` — 0, перестановок — 0 (6541 пакет).
- [x] Позиции — метры в пространстве трекинга (начало на полу: руки на высоте ≈ 0,92 м).
      `RootPose` совпадает с суставом 1 (запястье) → порядок соответствует `XrHandJointEXT`.
      Длины сегментов стабильны (σ 1,3–2,9 мм), `hand_scale` ≈ 1,04.
- [ ] Ориентации суставов: система осей и связь с позициями — определить при разработке методики
      15 суставных углов.
- [ ] Сравнить Hand Tracking Frequency High и Low (частота, пропуски, шум).
- [ ] Потери и задержки при нагруженной сети и длительной записи (≥ 4 ч по ТЗ).
- [x] Резервная запись на Quest создаётся и содержит те же кадры, что запись ПК (по 3085 на руку).
- [x] HUD (снимки экрана шлема): статус вверху слева, запись вверху справа, кнопки внизу; луч и подсветка
      кнопки при наведении; автоскрытие кнопок при начале записи; кириллица отображается.
- [x] Нажатие щипком и жест «меню» (ладонь к лицу + щипок) работают — подтверждено пользователем.
- [x] Наложение скелета поверх рук отображается (снимок шлема); точность совмещения оценить визуально.
- [ ] Ручной ввод IP с клавиатуры HUD.

Сеть: VPN-клиенты (v2RayTun на Quest, AmneziaVPN на ПК) должны пропускать локальную сеть мимо туннеля,
иначе поток не доходит. Проверка на Quest: `adb shell ip route get <IP ПК>` должно показывать `dev wlan0`.
