# Протокол QHS1 (Quest → ПК), версия 1

Рабочая спецификация потока кинематики рук. Реализации: `QuestHandStreamer/Assets/HandStreamer/Runtime/Protocol.cs`
(Quest, C#) и `pc-receiver/qhs/protocol.py` (ПК, Python). При изменении формата менять обе стороны и номер версии.

## Транспорт

- UDP по локальной Wi-Fi-сети. Все числа little-endian, структуры без выравнивания.
- ПК слушает порт **47000**, Quest — порт **47001**.
- Максимальный размер датаграммы — 1200 байт (меньше типичного MTU 1500 за вычетом заголовков IP/UDP),
  поэтому IP-фрагментации нет. Кадр одной руки с 26 суставами занимает 836 байт и всегда помещается в один пакет.

## Общий заголовок (12 байт)

| Смещение | Тип | Поле |
|---|---|---|
| 0 | 4 байта | magic = ASCII `QHS1` |
| 4 | u8 | тип сообщения |
| 5 | u8 | версия протокола = 1 |
| 6 | u16 | зарезервировано (0) |
| 8 | u32 | `seq` — сквозной номер пакета отправителя (общий для всех типов сообщений). По разрывам `seq` ПК считает потери, по убыванию — перестановки |

## Типы сообщений

| Код | Имя | Направление | Тело |
|---|---|---|---|
| 1 | HAND_FRAME | Quest → ПК | бинарное, см. ниже |
| 2 | STATUS | Quest → ПК, 1 Гц | JSON (UTF-8) |
| 3 | SYNC_REQ | ПК → Quest | `<I q`: sync_id, pc_t1_ns |
| 4 | SYNC_RESP | Quest → ПК | `<I q d d`: sync_id, pc_t1_ns (эхо), q_t2 (приём, с), q_t3 (отправка, с) |
| 5 | BEACON | ПК → broadcast:47001, 1 Гц | JSON: `{"pc_port":47000,"name":"..."}` |
| 6 | COMMAND | ПК → Quest | JSON: `{"cmd":"start"/"stop","id":N,"label":"..."}` |
| 7 | EVENT | Quest → ПК | JSON: `{"code":"...","session":"hex","mono":s,"ovr":s,"detail":"..."}` |

## HAND_FRAME — кадр одной руки

Отправляется только при появлении **нового** отсчёта трекинга (изменилась `SampleTimeStamp`). Повторно
прочитанные отсчёты не отправляются, а считаются в статистике (`dup`).

| Смещение | Тип | Поле |
|---|---|---|
| 12 | u64 | session_id; 0 — запись не идёт (живой поток) |
| 20 | u32 | frame_index — счётчик новых отсчётов этой руки |
| 24 | u8 | hand: 0 — левая, 1 — правая |
| 25 | u8 | source: 1 — непредсказанная поза (`GetUnextrapolatedHandState`), 2 — экстраполированная (`GetHandState(Render)`, только при явно разрешённом резервном режиме) |
| 26 | u8 | hand_confidence: 0 — low, 1 — high |
| 27 | u8 | bone_count N |
| 28 | 5 × u8 | finger_confidence (большой … мизинец), 0/1, 255 — нет данных |
| 33 | u8 | flags: bit0 — рука отслеживается, bit1 — input state valid, bit2 — есть позиции суставов, bit3 — есть ориентации суставов, bit4 — системный жест |
| 34 | u16 | зарезервировано |
| 36 | u32 | status — исходные флаги `OVRPlugin.HandStatus` |
| 40 | f64 | sample_time — `HandState.SampleTimeStamp`, с (время захвата трекинга) |
| 48 | f64 | requested_time — `HandState.RequestedTimeStamp`, с |
| 56 | f64 | ovr_now — `OVRPlugin.GetTimeInSeconds()` при формировании пакета |
| 64 | f64 | mono_now — `Stopwatch.GetTimestamp()/Frequency`, с, сразу после ovr_now |
| 72 | u32 | unity_frame — `Time.frameCount` |
| 76 | f32 | hand_scale |
| 80 | 7 × f32 | root pose: px py pz qx qy qz qw |
| 108 | N × 7 × f32 | суставы: px py pz qx qy qz qw |

**Координаты.** Позы записываются в исходном виде, как их возвращает OVRPlugin (`Posef`, `Quatf`,
`Vector3f`), без перевода в систему координат Unity. Пространство (tracking space), ориентация осей и
связь `BoneRotations`/`BonePositions` с root pose проверяются экспериментально и фиксируются в методике
до расчёта суставных углов.

## Временные домены и синхронизация

На Quest используются два домена:

- **ovr** — домен `SampleTimeStamp` и `OVRPlugin.GetTimeInSeconds()`;
- **mono** — `System.Diagnostics.Stopwatch` (монотонные часы; ими штампуются sync-ответы в фоновом потоке).

Каждый HAND_FRAME содержит пару (`ovr_now`, `mono_now`), снятую подряд. По ней ПК оценивает смещение и
дрейф ovr ↔ mono. Предположение, что `SampleTimeStamp` лежит в домене `GetTimeInSeconds`, проверяется
по условию `0 ≤ ovr_now − sample_time ≲ десятки мс`; при нарушении данные помечаются как
несогласованные.

Синхронизация mono ↔ ПК — NTP-подобный обмен: ПК отправляет SYNC_REQ с `t1` (`perf_counter_ns`), Quest
фиксирует `t2` (приём) и `t3` (отправка) в домене mono, ПК фиксирует `t4` при приёме ответа.

- RTT = (t4 − t1) − (t3 − t2)
- смещение θ = ((t2 − t1) + (t3 − t4)) / 2, т. е. mono ≈ pc + θ
- неопределённость одного измерения ≤ RTT / 2

Для оценки используются обмены с минимальным RTT; дрейф — линейная регрессия θ по времени.
Время прихода пакета по Wi-Fi **не** используется как время движения руки.

## Журнал записи `.qhslog`

Одинаковый формат на ПК и на Quest (локальная резервная копия).

```
"QHSLOG01" (8 байт) | u32 длина JSON | JSON-метаданные (UTF-8)
затем записи:  u8 dir (0 — принят, 1 — отправлен, 2 — заметка приёмника ПК) | i64 t_ns | u16 len | len байт пакета
```

`t_ns` на ПК — `time.perf_counter_ns()` в момент приёма/отправки; на Quest — mono-время в нс.
Журнал хранит исходные пакеты без преобразований; разбор и пересчёт времени выполняет `convert.py`.
